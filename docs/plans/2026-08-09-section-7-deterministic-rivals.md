## Goal

Make the 5-turn headless prototype feel competitive and strategically legible by adding two deterministic recurring rivals — **Mira** (storage/trade/flexible, moderate risk, reacts to shortage signals early) and **Daran** (farmland scale, aggressive, concentration risk, vulnerable to drought/cash pressure) — via plain integer scoring functions, real capital constraints, same shared economic primitives, structured threat context, and at least one visible rival headline per turn after the first. No LLMs, no generic pressure DSL, no DB.

---

## Success Criteria (maps to Section 7 AC 1–6 + global rules)

1. **Recognizably different choices (personality, not starting resources).** From the same observable context, Mira and Daran choose different commands often enough to be identifiable. Controlled test: given **identical** `RivalState` (same cash/inventory/farm/storage/route) and identical market context, `MiraProfile` vs `DaranProfile` produce different chosen `PlayerCommand.type` in ≥2 of 5 probe contexts (surplus / warning / drought / low-cash / storage-constrained). Canonical playthrough test (with unequal starts 1200/25/5/250 vs 1400/15/12/150) also shows behavioral fingerprint: over 5 turns Mira selects `build_granary|buy_grain|secure_route|ship_grain` more often than Daran, Daran selects `expand_farm` more often than Mira, and ≥3 turns have differing types.

2. **Deterministic.** Same `run_seed + ruleset_version + turn + rival_id + observable context` → same rival choice and same rival trajectory. Verified by `FiveTurnGame(seed="X").run(choices)` executed twice byte-equal: `rival_history`, final `RivalState`s, and headlines identical. Different choices diverge.

3. **Real capital constraints via shared primitives.** Rival execution reuses the **same extracted actor primitives** as player (`compute_farm_output`, `resolve_buy`, `resolve_storage_settlement`, `resolve_shipment` and same constants `500/300/400/800`, `YIELD_PER_CAPACITY=10`, `DROUGHT_YIELD_REDUCTION_BPS=4000`). If cash insufficient, quantity is clamped or command falls back exactly as `turn.py` does. Tests: cash never negative; zero-cash rival forced to `hold`; `assert rival_costs == player_costs` helper.

4. **No money creation (full accounting).** Rival wealth evolves only via same decomposition as player, now with price revaluation: `rival_wealth = cash + inventory*resolved_home_price//1000`, `wealth_delta = cash_effect + quantity_value_effect + price_value_effect`. Starting conditions are explicit (`MIRA_START`, `DARAN_START`) and documented; no hidden grants mid-run. Test asserts per-rival `wealth_delta == cash_delta + quantity_value(before_price) + price_value(final_inventory, before->after_price)` for each `RivalTurnResult`.

5. **Informs player choice (behavioral, not scripted).** Rival actions provide a legible signal. Under T3 warning context (`world_now=normal, next_world_known=drought`), Mira's scoring materially up-weights preparation/diversification (`build_granary|buy_grain|secure_route`) relative to baseline, and Daran remains more farm-concentrated than Mira (higher score for `expand_farm` than Mira in same context). Verified across several controlled contexts, not by hard-coding “T3 Mira must pick storage and Daran must pick farm.” Canonical 5-turn run remains a playthrough assertion that T3 produces divergent preparation vs concentration headlines truthfully reflecting actual resolved states.

6. **Included in reveals.** `FiveTurnGame.submit()` stores full `RivalTurnResult` history; `GameView`/CLI `6 MONTHS LATER` block renders at least one rival headline per turn after T1, derived from `RivalTurnResult.headline`. StrategicSummary includes per-turn rival headlines. Tests assert `len(rival_history)==5`, `rival_headlines` derived non-empty from T2 onward, and CLI output contains `MIRA`/`DARAN`.

7. **Housekeeping:** `engine`+`domain` stay pure (no `fastapi`/`sqlalchemy`/`httpx`), integers only (no floats, no `1e-9` fuzz), deterministic RNG via `rng_for` only on exact integer tie, structured threat context not prose parsing, `ruff` clean, `pyright` strict 0 errors, existing 96 tests green.

## Constraints And Non-goals

**Must satisfy:**
- Pure `engine`+`domain` — no `fastapi`/`sqlalchemy`/`httpx`/`asyncpg`/`openai`/`clerk`. Sync plain functions.
- Integer-only economics; determinism via `derive_seed`/`rng_for`; no `random` global, no `hash()`, no floats, no fuzzy epsilon.
- Shared actor primitives (see KDR #1) — single implementation for harvest/buy/storage/shipment.
- Structured observable threat context `world_now/next_world_known` (KDR #4), never `signal.contains("warning")`.
- Separate `RivalProfile` (personality) from `RivalState` (economic state) (KDR #5).
- Full `RivalTurnResult` history with exact wealth decomposition including price effect (KDR #6).
- Behavioral fingerprint tests across contexts (KDR #7), not one hard-coded T3 headline script.

**Explicitly out of scope (defer):**
- LLM rival decisions, chat negotiation, complex personality beyond two bps vectors.
- Third rival, route congestion, contested supply mutation of shared availability (rivals do not mutate `GameState.market.supply` in Section 7 — acceptable isolation).
- Generic content DSL / pressure arc framework (Section 8) beyond structured `next_world_known`.
- Balance harness sweeps (Section 9), FastAPI/GameView/revision (Section 10), React UI (Section 11), persistence (Section 16).
- Stale River info (Section 5 optional).

**Non-goals:**
- No new player commands; no `sell_grain`; no visual tableau beyond text headlines.

## Recommended Approach

Stay additive and keep the kernel as authority. First extract shared integer actor primitives into `backend/app/engine/actor.py` (≈120 lines) and refactor `turn.py` to call them — behavior-preserving, no new market logic. Then add pure `backend/app/engine/rivals.py` (≈260 lines) owning `RivalProfile`, `RivalState`, `RivalTurnResult`, bps preference tables, integer scoring with `rounding.py`, deterministic tie-break via `rng_for`, and headline templates derived from resolved outcomes. Keep `GameState` unchanged (session-owned rivals). Wire `FiveTurnGame` with the corrected two-phase timing: rivals **choose** from pre-turn `ObservableContext` (including structured `next_world_known`), player `resolve_turn` runs, then rivals **settle** via shared primitives at `pre_home_price / resolved_river_price / resolved_home_price`. Store full `rival_history` and derive headlines; account rival wealth with cash+quantity+price effects. Tests in `backend/tests/test_deterministic_rivals.py` prove personality under identical states, integer determinism, capital binding via shared primitives, no-creation with revaluation, behavioral preparation vs concentration, and visibility. CLI renders derived headlines.

This satisfies “author cause, simulate consequences” (warning → structured threat → scoring → rival action → headline), preserves truthful signals, keeps supply isolated, and avoids a generic DSL.

## Risks / Rollback

- **Risk:** Extraction of actor primitives changes player reason codes/deltas subtly. *Mitigation:* Behavior-preserving refactor with before/after comparison of `resolve_turn` DomainEffects; keep helpers integer-identical; run `test_turn_kernel` as gate before wiring rivals.
- **Risk:** Bps scaling overflow or ranking instability. *Mitigation:* Use `rounding.py` helpers, staged `//10000`, keep `expected_return` moderate (hundreds), test ranking determinism and exact-tie path.
- **Risk:** Structured `next_world_known` leaks future info beyond warning. *Mitigation:* Return `drought` only for T3 index 2; others `None`; score only up-weights on `==drought`, no gradation.
- **Risk:** Market coupling creep (rival supply mutating shared signal). *Mitigation:* Explicitly keep rivals isolated; test `player next_state.market.supply` equals standalone `resolve_turn` without rivals.
- **Rollback:** Revert `actor.py` extraction to preserve `turn.py` inline logic and keep `rivals.py` isolated; prototype wiring can be backed out with `git checkout origin/main -- backend/app/engine/prototype.py`.
