# Decisions

Record of accepted decisions that constrain implementation. `BUILD_SPEC.md` active Section takes precedence; this file records choices that refine it.

## 001 — Scope Strategy (2026-08-09)

- **Context:** The product vision in `BUILD_SPEC.md` Part I describes a multi-era dynasty game (8 economic regimes). The first playable is a 5-turn Agricultural grain prototype.
- **Decision:** `BUILD_SPEC.md` is the current implementation authority. Future systems (all eight ages, spoilage, credit, brands, automation, generic content framework, LLMs for rival economy) must not be built early without an active Section requiring them.
- **Scope contract (verbatim from `BUILD_SPEC.md:636`):**
  - the original product vision is intentionally broader than the first playable
  - this ordered specification is the current implementation authority
  - future systems must not be built early without an active section requiring them
- **Rationale:** Prove the core loop (observe → choose → commit → consequence → understand → adapt) before expanding scope. Keeps architecture concrete.
- **Consequence:** Agents work Section-by-Section, stop at each gate, and only update the `Status` line after acceptance criteria pass.

## 002 — FastAPI Conventions (2026-08-09)

- **Decision:** Follow [Beta Acid FastAPI Reference App](https://github.com/betaacid/FastAPI-Reference-App) conventions for the backend:
  - `Router -> Service -> Database Client -> Database` (and `-> Networking Client -> external API`)
  - Services and DB clients are plain module-level functions receiving dependencies as args; `Depends` only at the edge in `app/dependencies.py`
  - Classes only when holding real state/resources (e.g., `httpx.AsyncClient` pool)
  - File naming: `characters_service.py`, not `characters.py`
  - Async I/O (`AsyncSession`, `httpx.AsyncClient`), pure `domain/` stays sync
  - Transaction boundary in `get_db_session`; clients only `add`/`flush`
  - Lazy engine creation so imports don't require `DATABASE_URL`
- **Consequence:** `backend/app/engine` and `domain` remain pure and import no FastAPI/SQLAlchemy code.

## 010 — Five-Turn Authored Arc & Supply-as-Stock (2026-08-09)

- **Context:** Section 6 is the first multi-turn prototype. `MarketState.supply` was previously `next = stock + farm_output` with no consumption, which monotonically accumulated over repeated turns and would collapse prices. The review gate required defining supply semantics before building the 5-turn loop.
- **Decision:** Define `MarketState.supply` as a regional market-availability signal/index at the start of the turn, **not** a literal conserved physical stock. Home Valley signal evolves as `signal_next = max(0, signal + farm_output - demand)` where `demand` is the regional consumption index for the turn; price is set on `signal_next` via the existing `_target_price` guard (`max(signal_next,1)`). The same `farm_output` also enters player inventory — for this prototype no conservation is implied between the regional signal and player inventory (coherent ownership/flow accounting is deferred to Section 14). River Town signal remains stable (exogenous) for Section 6. `TURN_SPECS` is a hardcoded 5-element authored arc (T1 normal high demand, T2 normal surplus weak, T3 normal warning, T4 drought, T5 normal aftermath) with truthful prose that describes actual state (surplus emergent from accumulation, not per-turn harvest differences). Determinism is via choices (`same seed+choices → same`), not via seed variation, and cross-seed "no dominant strategy" is deferred to Sections 8/9 (but Section 6 now demonstrates tradeoffs, see AC5 non-dominance test).
- **Consequence:** The 5-turn game is bounded (no accumulation hack), signals are truthful, and the three scripted policies (farm-heavy, storage-heavy, trade-heavy) plus hold are each exactly 5 legal commands and diverge with tradeoffs. `FiveTurnGame` owns `GameState`+`history` outside the frozen `GameState`, calls `resolve_turn` once per turn with validated `rng_context`, and enforces exactly 5 submissions with `start_state.turn == 0`. CLI `backend/app/cli.py` is thin (interactive + `--choices` non-interactive).
- **Rationale:** Minimal coherent economics without requiring literal stock conservation; keeps the kernel as authority and makes the drought → farm_output → signal → price chain inspectable. A true physical-stock model with ownership would add unnecessary complexity for the 5-turn proof.

## 011 — Deterministic Rivals — Shared Primitives, Structured Threat, Integer Scoring (2026-08-09)

- **Context:** Section 7 adds Mira/Daran. The naive plan duplicated harvest/buy/storage/ship math in `rivals.py` with same constants, which would drift. Scoring used floats with epsilon tie, parsed signal prose for threat, and mixed personality with starting resources. History stored only headlines.
- **Decision:** (1) Extract shared actor primitives to `backend/app/engine/actor.py` (`compute_farm_output`, `resolve_buy`, `resolve_storage_settlement`, `resolve_shipment`, `value_for`/`cost_for_quantity` plus `YIELD_PER_CAPACITY`/`DROUGHT_BPS`/`COSTS`) and have both `turn.py` and `rivals.py` call them — `turn.py` keeps market resolution and trace, no generic engine. (2) Two-phase timing: rivals choose from pre-turn `ObservableContext{world_now, next_world_known, home_price_pre…}`, player/world market resolves, then rivals settle with `buy@pre_home`, `shipment@resolved_river`, `valuation@resolved_home`. (3) Integer/bps scoring `score = expected_return × pref_bps × capital_bps × risk_bps × exposure_bps` via `mul_basis_points`/`div_round_half_up`, prefs as bps (Mira 4500/15000/13000/14500 farm-averse, Daran 16000/7000 farm-hungry), exact integer tie → `rng_for(..., "rival", rival_id, 0)` only. (4) Structured threat `next_world_known` (`_next_world_known_for_turn(idx)==drought` only on T3 warning, derived from `TURN_SPECS` index, never `signal.contains("warning")`). (5) Separate `RivalProfile` (prefs/risk/exposure) vs `RivalState` (cash/inventory/farm/storage/route, no headline) with identical-state personality tests (≥2 diffs, Mira storage/trade > Daran, Daran farm > Mira). (6) Store full `RivalTurnResult{rival_id, before, command, after, headline, cash/qty/price/wealth deltas}` as `rival_history: tuple[tuple[Mira,Daran],5]`, derive `rival_headlines_history`, headline only in turn result. Wealth includes price revaluation `cash_effect+quantity_value_effect+price_value_effect`. (7) Replace scripted T3 headline assert with behavioral tests across surplus/warning/drought/lowcash/tight contexts (Mira prep > baseline and prep>farm on warning, Daran farm>prep, fingerprint suite). Rivals remain session-owned in `FiveTurnGame`, isolated from shared availability signal (isolation test), not in `GameState`.
- **Consequence:** No duplicated economy, stable integer determinism, threat drives behavior without prose parsing, personality proven independent of starting resources, full history enables determinism/debugging/API projection and correct no-money-creation invariant, behavioral tests avoid backward-designing scores to headlines.
- **Rationale:** Author cause (`TURN_SPECS` warning → structured `next_world_known`) then simulate consequences via scoring → rival action → truthful headline, keeping the same economic rules and timing as the player.

## 012 — Pressure as Turn-Derived Session-Authored Arc (2026-08-10)

- **Context:** Section 8 adds a world-pressure arc `normal→early_dry→worsening_dry→drought→aftermath`. The risk was storing pressure as canonical `GameState` field, creating a second source of truth that could hold `early_dry`+`drought` (F1/F2), and scattering the causal_source_id formula between domain and engine (F3). The 5-turn game is still in-memory (no persistence until Section 16), and rivals already model turn-derived `next_world_known` without canonical storage.
- **Decision:** (1) Model pressure in a distinct `backend/app/domain/pressure.py` (not `types.py` catch-all) as `PressureStage` literal + frozen `PressureState{pressure_id, stage, activation_turn, world, signal, title, causal_source_id}` — exactly 7 fields, no `world_modifiers`. Validator `mode="before"` populates `causal_source_id` + `mode="after"` enforces biconditional `stage=="drought" <=> world=="drought"` (every other stage => `world=="normal"`) and that `causal_source_id == f"pressure:{pressure_id}:{stage}"` (single source; explicit override must match or raise) (G6). (2) Author the single hard-coded `PRESSURE_ARC: tuple[PressureState,5]` in `backend/app/engine/pressure.py` (activation_turn==index validated at import, truthful rainfall prose, T2 title keeps `Surplus`, no JSON loader/weighted sampler/DSL) plus reusable `PRESSURE_NORMAL`/`PRESSURE_DROUGHT`/`pressure_for_world` constants for headless callers (G1). (3) Keep pressure **turn-derived/session-authored** (R1/F2): `FiveTurnGame` owns progression via `pressure_for_turn(idx)` / `next_world_known_for_turn(idx)` (only `worsening_dry→drought`, not prose parsing) and exposes `current_pressure: PressureState|None` (`None` when `is_complete`, else `pressure_for_turn(len(history))`); `TURN_SPECS` is derived `tuple(TurnSpec(world=p.world,... for p in PRESSURE_ARC))` for backward compat; `StrategicSummary.format()` appends pressure stage per turn (`T2 Surplus [early_dry]`) and `cli.py` displays `Pressure: stage` per turn header (G2). (4) `resolve_turn(state, command, pressure: PressureState, rng_context)` derives `world = pressure.world` internally and emits leading `pressure_stage` node (`kind="pressure"`, `delta=None`, `label` stage-derived e.g. `"Early dry conditions"` not title `"Surplus"` (G5), `reason_code=pressure.causal_source_id` directly, not recomputed) as parent of `world` (`pressure_stage→world→farm_output→home_supply→home_price→…→wealth`), preserving systemic `drought→farm_output→supply→price` and admitting via existing `trace.py` delta-None fallback (no validator loosening); `TURN_ORDER` updated to `pressure_stage -> world -> command -> ...`; no legacy string shim (G1, ~72 call sites migrated). (5) AC1/AC3 instrument is mechanism+warning-isolated: both histories share T1 `hold` (timing) and avoid `expand_farm` in either arm (so `home_supply` formula provably yields identical T4 market); test asserts equality pre-condition `supply 100==100`, `price 4750==4750`, `farm_output 60==60` (seed-8-useful) before asserting threshold-free exposure difference `price_value 130 vs 104`, `inventory 250 vs 200`, `wealth 130 vs 104` (fully affordable, no `insufficient_*`). (6) Structural smallness is proven by field count and file-text scan (no `json`/`random`/`weighted`/`sampler`), not line count.
- **Consequence:** Pressure is deterministic and inspectable (`pressure_for_turn`, `current_pressure`, trace) without canonical duplication, the invalid `early_dry+drought` state is impossible at construction time, the causal_source_id cannot silently diverge between domain and trace, and the warning usefulness test actually proves the warning mattered rather than that policies differ.
- **Rationale:** Single source of truth for `world` (one PRESSURE_ARC, one PressureState, one derive in `resolve_turn`) keeps the five-turn story coherent and anticipatory without adding a generic content framework until Section 15.

## 013 — Regional Non-Player Output & Balance Harness (2026-08-10)

- **Context:** Review round 1 proved the engine had a universally dominant "hold" strategy (hold 1909 vs production 548, optimal play is do nothing). Root cause: `signal_next = max(0, signal+farm_output-demand)` makes the player the entire supply side — expanding floods your own market and crashes price, and drought is invisible with farm 0. The ±2 supply perturbation was 0.3% and never flipped winner; a wide band (18 configs) still hold won all 18. Section 9's goal is to detect broken ranges before UI, and its stop condition says "stop when prototype is stable enough that UI playtesting is more valuable than additional headless tuning" — tuning is in scope.
- **Decision:** (1) Add one field `MarketState.regional_output: Quantity =0` (Home only, River stays 0). (2) New supply `signal_next = max(0, signal + regional_after + farm_output - demand)` where `regional_after` reuses the same `DROUGHT_YIELD_REDUCTION_BPS=4000` via `_regional_output_after_world` (single formula, no second constant). (3) Retune `default_start_state` to `supply 280/demand 400/regional 360/responsiveness 4000/storage 400` (was 100/90/5000/200) — player 100/460=21.7% (15–25%), demand roughly stable (surplus 60), price 3657-5381 within [2000,9000], storage cap no longer binding for production. (4) Trace `regional_output` node (parent `world`, `regional_output -> home_supply` alongside `farm_output -> home_supply`); `TURN_ORDER` extended with `regional_output`; `next_market.regional_output` preserved. (5) New `engine/harness.py` pure sync — 5 policies (production_heavy expand once, storage_heavy granary+buy20×2, trade_heavy route+buy+ship, cash hold×5, random_legal affordable via `rng_for`), `BatchConfig/run_batch` deterministic, `format_markdown/to_json` stable, gates: dominant `max_median/second <1.60`, dead `median≥0.70*overall` (no win_rate floor — deterministic win_rate is 0/1 by construction, seed variation from `random_legal` only), price `[2000,9000]`, negativity, swing ≤2500, determinism double-run, no bare-string `resolve_turn`. `cli --balance` prints markdown, writes JSON, exit 2 on breach (reported first, now blocking since tuned passes: 2073/2624/2752/3008 ratio 1.09). (6) Legitimate numeric updates only — TURN_ORDER + regional_output, supply 110→340/70→156 (now parents include regional), rival diffs 3→5 with new market (still ≥3), no deleted/loosened invariants; if invariant cannot hold, stop and report.
- **Consequence:** Drought now reaches price even with `farm_capacity=0` via regional (supply 96 vs 240, regional 216 vs 360), production not a self-harm trap, no dominant/dead by median-ratio (ratio 1.09, prod 2073 ≥0.70*2624), price within bounds, harness proves determinism and balance in <2s for 1000 games.
- **Rationale:** Lowest MVP complexity that makes BUILD_SPEC §2's chain literally true (`drought→regional output→supply→price`) and fixes dominance without market-share params, rival→supply coupling, new commands, second drought formula, or content DSL.

## 014 — Local Sell Channel & Hold-Not-Top Gate (2026-08-10)

- **Context:** Even after regional_output, `cash_preserving` (hold×5) still had highest median (3008) and won 100% of seeds. Root cause: no way to sell grain — the six verbs were expand_farm, build_granary, buy_grain, hold, secure_route, ship_grain; `cli.py` even aliased `sell`→`ship_grain` misleadingly. Grain accumulated to the storage cap (400, which binds for every strategy including hold) and was then thrown away; wealth = cash + inventory*price, so producing more lowered price and was a worse farmer. No amount of constant-tuning can fix a missing monetization path. BUILD_SPEC §6 Turn 5 lists "selling inventory" and §17's advisor returns `["sell_stored_grain","preserve_cash"]` — it was assumed, never implemented.
- **Decision:** Add `sell_grain` with `quantity` mirroring `buy_grain` as its inverse, reusing shared actor primitives (`resolve_sell` next to `resolve_buy` in `actor.py`, same integer/milliunit `cost_for_quantity`/`value_for` and rounding). Converts grain→cash at current Home price, clamped to inventory (`insufficient_inventory` when `requested > inventory`). Both player and rivals can use it — rivals via `actor.resolve_sell` in `apply_rival_command` and scoring (`_expected_return` for sell, `_capital_bps`/`_risk_bps` handling, `choose_rival_command` candidates, `RivalPreferences.sell_grain` 14000 Mira / 9000 Daran, headlines `sell_grain`/`insufficient_inventory`). Causal nodes `inventory_after_sell` (and alias `inventory_after_buy` for downstream valuation) and `purchase_quantity_value` now handles `sell_grain` (`sell_quantity_value` with negative delta). CLI: `sell`→`sell_grain` (fix misleading alias), `ship` stays `ship_grain`, new aliases `5:sell_grain` `6:secure_route` `7:ship_grain`; `parse_choice` handles `sell_grain`/`buy_grain`/`ship_grain` quantities. Harness: `storage_heavy` now `granary T0, buy 20 T1-2, sell 30 T3-4` after drought spike; `random_legal` includes `sell_grain`; new gate `hold_not_top` — `cash_preserving` median must NOT be max (at least one active strategy beats holding), median-ratio/dead gates kept. Retune: keep `supply 280/demand 400/regional 360/responsiveness 4000/storage 400` — storage cap still binds (hold 400/400, storage 450/450) but granary now gives +50 headroom and sell realizes gains; with sell, storage 3055 > hold 3008, hold_not_top PASS, median ratio 1.02, no dead, price 3657-5381. No other mechanics: no contracts/spoilage/credit/multiple goods/price-impact-of-sales.
- **Consequence:** Storage now monetizes (buy low, sell high) and beats holding (3055 vs 3008, wins 97.5% vs hold 0% with 200 seeds; random 2.5% due to sell variation). Production 2073/2624/2752/3008 all within 0.70*overall, price within bounds, determinism and all invariants still hold. Poor rival with inventory now correctly sells instead of holds.
- **Rationale:** Real payoff channel makes BUILD_SPEC's core thesis true (committing resources beats passivity); minimal verb reuse keeps complexity low and keeps rival/player on same primitives.
## 015 — Farm Baseline Lowered and Harness Policies Made Competent — Hold Rank ≥3 Binding Constraint (2026-08-10)

- **Context:** After 014, hold_not_top passed by only 1.6% (storage 3055 vs cash 3008) and flipping storage 400→500 put holding back on top — knife-edge tuning. Root cause measured: starting farm 10 → 100 grain/turn free, over 5 turns 20+500=520 against 400 cap, so doing nothing saturates cap by turn 4; incremental capacity has nowhere to go, which is why expand_farm underperforms and idling captures nearly the maximum. Sweep with sell available shows farm 3-6 all still hold rank 2 with old small buys.
- **Decision:** (1) Lower starting `farm_capacity` from 10→5 (tune empirically, 5 not sacred) so free baseline 50/turn, 250 over 5 turns, 20+250=270 <400, so cap constrains ambitious players not idle ones. Player share drops from 21.7% to ~12.2% (50/410), so `demand 400→410` to keep surplus ~0 and drought bite (regional 360→216, farm 50→30) still 280→116 supply. (2) Make each harness policy a competent expression scaled to cash and storage headroom and selling into post-drought price peak: `production_heavy` expands when affordable then sells only at peak turn 4 (up to 150), `storage_heavy` builds granary then buys `min(space, affordable, 80)` pre-drought and sells only at peak (up to 150), `trade_heavy` secures route then buys scaled and ships/sells only at peak. All buys now `min(space, max_affordable, 80)` not hardcoded 10/20. (3) Replace hold_not_top (not max) with strictly stronger gate `hold rank ≥3` — `cash_preserving` must rank no higher than 3rd of 5 (≥2 policies beat it), median_ratio <1.60 and dead ≥0.70 kept. No new verbs/mechanics beyond sell_grain.
- **Consequence:** With new competent policies and farm5, 200-seed harness: production 2977 storage 2927 trade 2990 cash 3133 random 2408 — cash rank 1/5, hold_not_top FAIL (0 beat, need 2), ratio 1.05 PASS, dead PASS, price 3876-8535 PASS. Sweep farm 2-10, supply 280-600, demand 340-420, regional 280-400, resp 3000-6000, cap 250-450, costs 150-500 shows no config achieves rank ≥3 with price staying in [2000,9000] under current 20%/turn movement cap and granary 300 cost — arbitrage profit ~300-400 per 80 grain insufficient to overcome hold's free 250 grain valued at high final price plus preserved cash. Lower farm makes production win but storage/trade still ~100-200 short; higher resp makes trade barely beat but pushes price >9000. Tests updated legitimately: supply 340/156→280/116, supply node 340→280, canonical diffs 3→1, drought preparation relaxed.
- **Rationale:** Investment must produce storable sellable grain rather than overflow; policies must represent how a smart player would actually play that style scaled to resources, not strawman small buys, otherwise balance table is not evidence. If honest tuning cannot meet rank ≥3 without breaking price band, report binding constraint and missing mechanic (farm maintenance/diminishing returns, storage beyond arbitrage, or trade margin) rather than fudge gate or add mechanics unilaterally.

## 016 — Matched Controls, Policy Bug Not Economy Bug, Route Reverted, River Retracted, Price-Taking Boundary (2026-08-10)

- **Context:** 015 concluded no start-state can clear hold rank ≥3 and a new mechanic was required. Round 2 proved that wrong by varying the two unswept binding params (storage 400→130, route cap 20→60, transport 800→300) and fixing two strawmen, reaching green at 132 passed. Round 4 then applied the matched-control technique — run the identical policy with that single defining command suppressed (not vs hold) — which surfaced that the green was still fragile: build_granary was -21 on 300 (-7% trap, same state secure_route was in) and route capacity 60 was unnecessary. Both were measured without the control.
- **Decision:** (1) Fix third strawman `policy_storage_heavy`: build only when incoming harvest would overflow (`inventory+farm*YIELD > storage`, turn<4) and buy only into headroom harvest will not claim (`headroom = storage - (inventory+harvest)`, buy `min(headroom, affordable, 80)` at turns 1-2, sell at peak 4). This stores free harvest (~8.5/unit) not purchased grain (~2.6/unit) and flips granary from -21 to +54 median with no constant tuning; keep `BUILD_GRANARY_COST 300` and `DELTA 50` unchanged. (2) Revert `route.capacity 60→20` and keep `transport 300` (transport was entire route fix: at 300, cap20 gives +174 on 400 cost =43.5% return, cap40 +311, cap60 +280; at 800/500 route destroys 224-300 regardless of cap or River size). Keep `river_market` at `80/130` — round 3 proposal 200/350 is **retracted** as invalid: `MarketState.supply` is an availability signal/index, not conserved physical stock, river supply is held constant and shipments never feed back, so shipped-to-supply ratio measured nothing (R4). (3) Keep `storage 130` and `transport 300` — net change vs original start state is two numbers: `storage 400→130` and `transport 800→300`, plus three policy fixes. Final measured at n=40: `storage 2345 (+11%)`, `production 2290 (+9%)`, `trade 2241 (+6%)`, `hold 2109`, `random 1738` — hold rank **4/4 intentional** (3/3 active beat hold by ≥5% material: `active*10000 ≥ hold*10500`), ratio `10240 bps` (1.024) PASS (<16000), dead PASS (overall median 2241, worst 2109*10000=21M ≥15.6M), price 3876-8535 PASS. Trade is weakest of three at +6%, not overstated.
- **Consequence:** Matched controls now falsifiable: `test_build_granary_not_worthless` keeps headroom necessary condition plus `test_granary_incremental_matched_control` asserts `storage_heavy` vs itself with `build_granary` suppressed median >0; `test_route_can_repay` asserts `trade_heavy` vs itself with `secure_route` suppressed and harness reports `trade_wealth 2241`, `trade_without_route_wealth 2067`, `route_incremental_value +174`, `route_incremental_value_bps_of_cost 4350`. Harness gates converted to integer bps: `win_rate_bps`, `median_ratio_bps`, dominant `top*10000 < second*16000`, dead `med*10000 ≥ overall*7000`, hold `active*10000 ≥ hold*10500` over 4 intentional; tie handling fixed to `tied_best_count` + `unique_wins` (deleted biased decrement loop). Price envelope made exact: `abs(after-before) ≤ before*max_movement_bps//10000` reading from state, no +500 loosening. BUILD_SPEC Section 9 was COMPLETE with granary trap and float gates; set back to IN PROGRESS until all above pass, then COMPLETE.
- **Alternatives considered and rejected:** (1) Upkeep/settlement consumption swept 20-70 and capacity-scaled variant moves hold 1→2 never 3, blows ratio to 2.04 at 40 and 5.01 at 60 — trades one dominant for another, rejected. (2) Spoilage per BUILD_SPEC §15 deferred to Section 14, not implemented. (3) Tuning `BUILD_GRANARY_COST/DELTA` swept and unnecessary — policy bug masquerading as economy bug (same error as 015 reverse). (4) River rescale 80/130→200/350 proposed to keep shipments ~20% of supply, retracted after second reviewer caught supply-is-signal (R4) and after matched control showed route repays at 20 with River untouched.
- **Rationale:** No new mechanic/verb/state field, integers only, pure engine via `rng_for`, price-taking boundary stated explicitly: player sales/shipments are price-taking in five-turn prototype, endogenous impact deferred to Section 14; transaction sizes/costs tuned only enough approximation remains usable. Widest-margin tuning avoids knife-edge (014 1.6%).

## 017 — Section 10 Minimal FastAPI Boundary — No Strategy Gatekeeping, Two Quantities, Per-Session Lock, Trace & History Discipline (2026-08-10)

- **Context:** Plan review B1 exposed that `available_choices` was gated on turn index and `margin>0` lifted from `harness.py` scripted policies (turn heuristics are measuring instruments, not rules). C3/C4 found `completion_summary: StrategicSummary` smuggled full history (5 traces) contradicting Section 10's excluded history endpoint and B2's "latest turn only", and conflated top-level next-decision context with latest-outcome context. Engine has single pure helper needed for ship margin.
- **Decision:** (1) **No strategy gatekeeping** — `available_choices` is a transport/presentation projection derived from **legality + affordability only** (`cash >= cost`, `not established`, `inventory>0`, `headroom>0`); no `turn<4` / `turn in (1,2)` / `turn==4` / `turn==0` / `margin>0` gating. Harness policies never influence player authorization. `ship_grain` offered even when `next_margin<0` — loss is a legal mistake the player may make. Falsified by `test_available_choices_turn_invariant`. (2) **Two quantities per verb** — partial + full commit (e.g. `buy_grain:30` + `buy_grain:60` where `max_buy = min(headroom, affordable, 80)`, `sell_grain:10`+`20`, `ship_grain:10`+`20`) — one amount removes depth-of-commitment (Section 9 showed scaled buys mattered), a slider would violate BUILD_SPEC 4; two keeps list ~6–8.
